Лог промтов, которые использовались для генерации кода и архитектуры агентом. Включает неудачные попытки, чтобы не наступать на те же грабли.

### 1. Генерация парсера (Успешный подход)

**Prompt:**

```text
Напиши функцию на Dart/Python, которая принимает строку и возвращает объект Card(front, back) или null.
Правила:
1. Ищи самый левый разделитель из списка: длинное тире '—', среднее '–', дефис с пробелами ' - ', двоеточие ':', равно '='.
2. Дефис без пробелов игнорируй.
3. Раздели строку по первому найденному разделителю.
4. Обрежи пробелы по краям у обеих частей.
5. Если любая из частей пустая — верни null.
Примеры для теста: "Производная — скорость", "Время: 10:30", "E = mc²", "кто-то пришёл".
```

**Результат:** Работает отлично. Использование одного Regex с группировкой `(?:\s-\s|—|–|:|=)` и метода `split(regex, maxSplit: 2)` решает проблему «самого левого» разделителя нативно.

### 2. Неудачный промт: Попытка сделать парсер через последовательный replace

**Prompt (НЕ ДЕЛАТЬ ТАК):**

```text
Замени в строке все тире, двоеточия и знаки равно на специальный символ |, а потом раздели строку по этому символу на две части. Учти, что дефис без пробелов заменять не надо.
```

**Почему провалился:**

1. Если в строке `Время: 10:30` заменить все двоеточия на `|`, получится `Время| 10|30`. Разделение по первому `|` даст правильный результат, но если использовать глобальный replace, можно сломать данные.
2. Спецификация требует искать _самый левый_. Если строка `A = B : C`, то замена всех символов на `|` даст `A | B | C`. Но если мы ищем первый, нам нужно знать его оригинальный индекс. Массовый replace стирает информацию о том, какой разделитель был первым, если они разные.
   **Вывод:** Только посимвольный проход или `Regex.firstMatch`.

### 3. Генерация UI реактивности (Пересчет карточек)

**Prompt:**

```text
У меня есть TextField с многострочным текстом. Мне нужно, чтобы при каждом изменении текста (onChanged) вызывалась функция parseText(text), которая возвращает List<Card>. Внизу экрана должен обновляться Text("Найдено карточек: ${cards.length}"). Кнопка "Создать" должна быть disabled, если cards.isEmpty. Напиши это используя Riverpod/BLoC/useState.
```

**Нюанс, который пришлось уточнять:**
Первый сгенерированный код пересчитывал карточки слишком часто (на каждый ввод символа), что вызывало лаги, если текст большой.
**Уточняющий промт:**

```text
Добавь debounce на 300ms для onChanged в TextField, чтобы парсер не вызывался на каждое нажатие клавиши, а только когда пользователь остановил ввод.
```

### 4. Неудачный промт: Логика экрана повторения (Очередь)

**Prompt (НЕ ДЕЛАТЬ ТАК):**

```text
Сделай экран повторения. Покажи карточки по одной. Если нажал "Не знаю", покажи её снова позже. Если "Знаю", перейди к следующей. В конце покажи сколько знал с первого раза.
```

**Почему провалился:**
Агент сгенерировал код, где при нажатии «Не знаю» карточка просто показывалась _следующей_, ломая порядок других карточек, или использовался `while(true)` цикл, который блокировал UI поток. Кроме того, агент забыл сбрасывать состояние "перевернутости" карточки, когда она уходила в конец очереди.
**Исправленный промт:**

```text
Реализуй машину состояний для повторения карточек.
1. Используй Queue (очередь) для хранения ID карточек.
2. Инициализация: перемешай список карточек и добавь в Queue.
3. Состояние экрана зависит от queue.first().
4. Действие "Знаю": queue.removeFirst(), decrement counter K.
5. Действие "Не знаю": card = queue.removeFirst(), queue.addLast(card), set firstTryMap[card.id] = false. Reset isFlipped state to false.
6. Условие конца: queue.isEmpty().
7. Считай X как количество элементов в firstTryMap, где значение true.
Напиши это без циклов while, только реактивно на нажатия кнопок.
```

### 5. Работа с ML Kit (OCR)

**Prompt:**

```text
Напиши код для Flutter, который берет файл изображения, передает его в ML Kit Text Recognizer, дожидается результата и возвращает String. Учти, что нужно распознать русский и английский.
```

**Проблема:** Агент по умолчанию использовал латинский скрипт (`TextRecognitionScript.latin`). Русский текст превращался в кракозябры или игнорировался.
**Уточняющий промт:**

```text
Используй TextRecognizer из пакета google_mlkit_text_recognition. Явно укажи использование кириллического скрипта (Cyrillic) и латинского (Latin). Если API требует выбора одного скрипта, используй Cyrillic, так как он включает базовые латинские символы для формул вроде E=mc2, либо инициализируй два распознавателя и объединяй результаты.
```

_(Примечание: в реальности ML Kit v2 поддерживает мульти-скрипт или требует скачивания конкретных моделей. Пришлось вручную править код агента, чтобы подтянуть `TextRecognitionScript.cyrillic`)_.

### 6. Форматирование даты для названия набора

**Prompt:**

```text
При нажатии "Создать карточки" сгенерируй имя набора в формате "Конспект ДД.ММ ЧЧ:ММ" используя текущее время устройства.
```

### 7. Неудачный промт: Сохранение фото

**Prompt (НЕ ДЕЛАТЬ ТАК):**

```text
Когда пользователь выбирает фото, сохрани его в базу данных вместе с карточками, чтобы показывать превью в списке наборов.
```

**Почему провалился:**
Прямое нарушение спецификации: «Сами фото и результаты повторений не сохраняются». Агент попытался конвертировать картинку в Base64 и запихнуть в SQLite, что раздуло БД и замедлило приложение.
**Исправление:**
Явно указал агенту: «Превью фото нужно ТОЛЬКО на экране 'Распознанный текст'. Держи его в RAM как File object или временный URI. При переходе на главный экран удаляй ссылку. В БД сохраняй только текст».
